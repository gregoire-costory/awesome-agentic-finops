# Contributing

This list is maintained in the open. Pull requests are welcome from anyone, including vendors and direct competitors, under the same rules.

## Inclusion criteria

An entry qualifies if it meets all of these:

1. **Relevant.** It helps people understand, allocate, forecast, or reduce cloud cost (FinOps), or it is an agentic interface (MCP server, assistant skill, agent) to do so.
2. **Real and maintained.** It is usable today and has seen activity in roughly the last 12 months. Hackathon-only or abandoned repos are excluded unless historically notable.
3. **Honestly available.** Open source, an open spec, or a commercial tool with a genuine way to try it. Commercial tools are allowed but must carry the `vendor` tag.

## The `vendor` tag and disclosure

Entries from companies that sell a FinOps product are tagged `` `vendor` `` so readers can see the commercial interest at a glance. This list is maintained by Costory, which is a vendor, so the Costory entry carries the tag too and is held to the same bar as everyone else. If you think any entry (ours included) does not belong, or is described too generously, open an issue or a PR. Removal and rebalancing PRs are fair game and will be reviewed on the merits.

## Annotation style

- Format: `` - [name](link) `vendor?` - Factual description, who it is for. ``
- Describe what the tool does, not how good it is.
- **No negative editorializing about competitors.** The comparison table states checkable facts only (clouds, license, delivery, whether it can act, whether it models business context). "Stale", "limited", "the best" do not belong here. Neutrality is the entire value of the list.
- Keep entries in their most fitting section and in keeping with the surrounding ordering.

## Comparison table

To add a tool to the table, fill every column with a checkable fact. If you do not know a cell, say so in the PR rather than guessing. "Acts" = can take an action (alert, report, annotation), not only answer. "Context" = models allocation or unit economics, not only raw service spend.

## Not sure?

Open an issue and ask. A rough suggestion is better than none.
